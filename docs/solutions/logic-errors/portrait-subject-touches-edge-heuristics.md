# 人像证件照让"背景在四边、主体在中间"的假设失效（白衬衫被去除、误报非纯色、头部过小）

## Problem

去背景最初面向白底产品图和图标：主体在画面中间，四条边都是背景，主体里与背景同色的区域被主体完整包住。换底色 / 证件照把输入扩展到人像后，基于这些假设的三处启发式都出了错：衬衫被当成背景、纯色背景被判为不是纯色、自动构图把头框得太小。

## Symptoms

- 真实证件照（白墙、黑西装、白衬衫）换蓝底后，衬衫领口大片变蓝，阴影处留下白斑。调容差只能在"衬衫去得更多"和"发丝更差"之间取舍。
- 同一张照片 `border_match` 为 0.63，触发"背景不是纯色"警告（阈值 0.9）。
- 头肩识别结果为空，框退回"框住整个主体"，几乎是整张图。

## What Didn't Work

- 用合成图验证：第一版只用"圆形头 + 矩形身体"的合成图测试，单测和导出图都正常。合成图里衣服和背景颜色不同，也没有领口这种细缝，真实照片的三个问题一个都没暴露。
- 边缘匹配率忽略最差的一条边：只能应付主体贴一条边的情况。半身照的西装同时占满底边和左右两边的下半段，匹配率还是只有 63%。
- 把头宽定义为"肩膀出现前的最大行宽"：真实西装的肩膀从脖子往外是逐渐变宽的，行宽一直没有一行超过已累计最大宽度的 1.5 倍，肩膀永远检测不到。另外照片右边缘有一条 2px 的灰线，让每一行的"最右不透明像素"都在图片边缘，行宽全部被撑满。
- 只依赖洪水填充的"与边缘相连"：白衬衫在领口处和白墙直接接触，同色像素是连通的，洪水填充顺着领口灌进了整块衬衫。

## Solution

1. 人像模式（`BackgroundRemoval.portrait`，换底色默认开）用可见性代替连通性（`keep_only_visible`）：先全图按颜色算背景程度，再从每行左右两端、每列顶端向内扫描，只有沿直线能"看到"的背景像素才算背景。允许越过不超过约 0.8% 短边的非背景像素（发丝、边框细线），遇到脸、西装这种宽遮挡就停下。衬衫在每一行都被西装挡住，在每一列都被下巴挡住，所以保留；发丝之间的小块背景沿直线可见，所以能去掉，比洪水填充效果更好。
2. 人像模式的边缘匹配率只看上边和左右两边的上半段，并向内缩 2-8px 避开边框线（`portrait_border_match`）。
3. 头肩识别（`subject_bounds`）只统计连续不透明达到一定长度的片段，忽略边缘细线和噪点；行宽回落到头部最宽处 85% 以下（到了脖子）之后，不再把行宽计入头宽，这样逐渐变宽的肩膀也能在超过头宽 1.5 倍时被识别。

## Why This Works

产品图的同色区域通常被主体完整包住，"与边缘连通"等价于"是背景"。人像不是这样：衣领、衬衫会在细缝处碰到背景。人像构图里背景只出现在人物轮廓之外，而轮廓之外的区域从图片左、右、上边缘沿直线一定能看到。这个可见性约束正好排除了"颜色相同、连通、但被身体挡住"的区域。头宽同理：证件照关心的是头部，以脖子为界切开，比依赖"肩膀突然变宽"可靠。

## Prevention

- 去背景、构图类改动必须用真实照片验收，不能只靠合成图。合成图要刻意包含与背景同色、并在细缝处接触背景的区域（`background::tests::suit_on_white`），以及边缘细线。
- 构图类改动除了断言数值，还要导出结果图并放大关键部位（领口、发丝）看一眼。期望值是照着算法写的，算法本身错了的时候断言照样通过。
- 可见性规则的已知盲区：衣物在某一行直接连到背景（不穿外套、侧身）时仍会被去掉；浅色头发、灰墙的发丝边缘只能按颜色过渡。这类照片需要语义抠图模型，颜色规则无法解决。
