# AI 重绘出的设计稿图标含义不对：根因是误识别和原图过小，放大设计稿解决不了

## Problem
用户的申报页（1086×1448）识别出 10 个"图标"，AI 重绘后多数含义不对，第一反应是"图标太糊，把设计稿放大再识别"。查 spec 发现 10 个里只有日历、门店、勾选框是真图标，其余 7 个是文字、徽标和列表圆点；真图标的重绘结果本来就是对的。

## Symptoms
- 参考图网格里是数字、汉字和 8px 圆点放大后的模糊色块。
- 没有命名的图标，提示词只能写"照参考图画"，模型只看到孤立的小块。

## What Didn't Work
- 放大设计稿再识别（假设）：框是按原图像素算的，位置本来就准；插值放大不增加信息，8px 圆点放大后还是一团；AI 超分本身也是生成，小图标细节一样会被猜。误识别是归类规则的问题，和分辨率无关。
- 实心块并回文字行的规则只拿"普通笔画"当同伴：粗体数字「2026」里 0 和 2 都是实心块，"2" 的邻居全是实心块，没有可依附的笔画，于是落单成图标。
- 用 `hb`（核心外框）算实心度：组件的抗锯齿边缘在 `hb` 外面，字的实心度被算到 0.88-1.03，全被当成"填满的矩形"排除。
- 用全部像素做列投影判断「01」是两个字：0 和 1 之间的抗锯齿像素把空列填上了，投影只有一段。

## Solution
`crates/imgspec/src/segment.rs`、`pieces.rs`、`icons.rs`：
- 实心块并回文字行改成迭代：已并回的实心块也作为后续判断的同伴，一个带一个；整行都是实心字时，≥3 个同行同色、高度相近、紧挨着的实心块直接按文字处理。只有"像字"的块参与（实心度按组件外接框算 < 0.85），并排的标签色块不受影响。
- 长边小于画面短边 1.2%（至少 12px）的小块归为 rect，不当图标。
- 列投影只统计"实"的墨迹（与底色距离 ≥ 0.6 × 墨迹色与底色的距离），能切成 ≥2 段占满高度的块按文字处理；偏旁等矮块允许存在但不超过 30% 宽度。
- 宽高比 > 1.25 的小色块不整体折叠成图标（徽标里是文字）。
- 重绘门槛：默认跳过原图长边 < 24px 的图标并说明原因，全都太小时直接报错不花额度；显式 `ids` 或桌面端勾选可强制。
- 补含义：多传一张"完整设计稿上红框 + 编号标出图标"的上下文参考图，提示词写入离图标最近的已标注文字；返回未命名的图标列表，提示先命名。

## Why This Works
重绘结果取决于模型拿到的是不是一个"有含义的图标"。误识别送进去的是字和点，什么分辨率都画不对；真图标即使模糊，有了它在页面上的位置和旁边的文字，模型也能判断含义。实测这张图修复后不命名直接重绘，日历、门店、勾选框 3 个全部画对。

## Prevention
- 图标质量问题先查 spec 里每个 icon 节点的原图尺寸和它实际是什么，再决定是识别问题还是画质问题。
- 回归测试：`crates/imgspec/tests/regressions.rs` 的 `dense_bold_digits_stay_in_text_line`、`number_badge_is_frame_with_text`、`list_bullets_are_not_icons`；`tests/workflow.rs` 的 `redraw_skips_tiny_icons_and_adds_context`。
- 合成测试图要用接近真实的画布尺寸（如宽 1086）：`text_max_h` 等阈值随画布变化，400px 宽的测试图里 26px 的字会超过文字高度上限，测出来的不是真实行为。
- 判断"实心度""空列"这类像素统计时，排除抗锯齿边缘（用组件外接框、只数强墨迹），否则对小字号结论会翻转。
