# 设计稿解析在合成图上全部通过，换成 AI 生成的 UI 稿就把卡片、按钮、文字认错

## Problem
imgspec 的色块分层和笔画合并规则是按合成图（纯色、严格线性渐变、无噪点）写的，测试全过；用 `generate_image` 生成真实 UI 稿验收时，卡片、按钮、文字行大量识别错误。合成图里不存在的几种性质把规则推翻了。

## Symptoms
- 商品卡片：白卡片里放着浅灰底的商品图，整张卡片被判成 image。
- 登录按钮（胶囊形、带高光的紫色渐变）被判成 image。
- 标题和价格两行字被合成一块。
- 渐变按钮内部出现很多低对比"图标 / 色块"；微信、QQ 这类圆形徽标的白色图案在素材里被挖空。

## What Didn't Work
- 先假设"连通块的众数色就是卡片底色"：商品图比卡片留白面积大时，众数色是商品图的底色，核心框只覆盖图片，后面的边缘检查全部失败。
- 只放宽渐变的颜色容差：按钮能认出来了，但内部递归仍用全局阈值，非线性高光变成一堆碎块。
- 近邻合并加"合并后高度不超过 1.5 倍"的限制：仍然串行。union-find 在一轮里传递合并，标题 ~ 噪点 ~ 噪点 ~ 价格每一对都满足条件，整条链一次全并了。

## Solution
`crates/imgspec/src/segment.rs`、`pieces.rs`、`icons.rs`：
- **与页面同底色的内容**：商品图底色（#f1f1f1）和页面底色（#eeeff1）差不到阈值，卡片连通块中间是空的、实心度 < 0.55。新增 `ring_closed`：外圈四边中段都闭合且尺寸大于图标的块，仍按色块处理（核心密度阈值从 0.3 降到 0.06）；众数色失败时再用外框内侧一圈的众数色重试（`try_filled_box` → `filled_box_with`）。色块范围内没连上的元素和色块都交给递归，不在父级重复出现。
- **胶囊 / 大圆角**：检查"三条边内侧是填充色"时，允许向内找 `min(w,h)×10%` 像素，弧线两端才能通过。
- **非线性渐变**：纯色只解释 < 85% 时也试渐变，覆盖更大就用；核心容差取 `max(1.5×阈值, 3×残差)`（≤30），残差 > 12 的视为照片。内部递归用这个放宽后的阈值（`BoxHit.thr`），渐变底上与所在位置底色 ΔE < 12 的叶子直接丢弃。
- **噪点串行**：合并前先丢掉 < 5 像素的孤立噪点；零星小块（≤ 2×近邻距离）只并入离它最近的大块，且只并像素、不扩大外接框；大块之间才做 union-find。
- **照片 vs 色块**：色块里有对比度明显（ΔE ≥ 30、字号 ≥ 10）的文字时不整体折叠成 image，只删低对比叶子碎块；不含可读文字的小方块（App 图标、手机/锁形状）整体折叠成 icon。
- **图标去底**：只去掉从四周连通过来的底色；不透明部分 ≥ 45% 的实心徽标保留内部被包住的白色图案，线性图标内部仍透明。

## Why This Works
合成图的三个隐含假设在 AI 稿里都不成立：内容面积可以大于容器底色，并且颜色和页面底色接近；渐变带高光、不是严格线性；画面有大量 1-3 像素的压缩噪点。修复把判断从"整块的统计量"（众数色、实心度）改成"边界结构"（外圈闭合、边缘颜色），并把阈值跟随局部底色模型的残差走，同时阻断 union-find 经由噪点的传递合并。

## Prevention
- 新的分割规则必须同时过合成图和真实稿：`cargo build --release -p imgspec --example analyze`，对 `.imgtool/spec-eval/gen/` 下的真实稿跑 `--out` 看标注图，单个区域用 `--crop x,y,w,h` 复现。
- 真实稿暴露的问题先写成合成复现测试再修：`crates/imgspec/tests/regressions.rs`（胶囊渐变按钮、与页面同底色的卡片内容、噪点不串行）、`icons.rs` 的 `keeps_enclosed_white_details`。
- 用 union-find 做"相邻即合并"时，任何"合并后不能超过 X"的约束都对传递链无效；要么限制参与者（小块只挂靠、不互连），要么在合并后再校验并拆分。
